## 5. 미배정 0건 — 검증 방법

이 문서의 주장을 기계로 확인하려면:

```bash
# 1) 이 문서가 참조하는 Stage 가 전부 02-stages.md 에 실재하는가
#    주의: 헤딩 `## S8 · S9 — 퇴역 번호` 처럼 한 줄에 둘이 있으므로 줄 전체에서 뽑는다.
#    `^## S[0-9]+` 로만 뽑으면 S9 를 놓쳐 "미정의" 거짓 양성이 난다 (실제로 처음에 그랬다).
grep -oE "\bS[0-9]+\b" review/05-coverage.md | sort -u > /tmp/refd.txt
grep -E "^## S" review/02-stages.md | grep -oE "\bS[0-9]+\b" | sort -u > /tmp/defined.txt
comm -23 /tmp/refd.txt /tmp/defined.txt    # 출력이 있으면 = 존재하지 않는 Stage 참조

# 2) 퇴역 번호(S8·S9)가 배정에 쓰이지 않았는가
grep -nE "\*\*S[89]\*\*" review/05-coverage.md   # 무출력이어야 한다

# 3) 감사 원본의 non-OK 총수와 §1 의 행 수 대조
#    T1 14 / T2 23 / T3 15 / T4 4 / T5 19 = 74
```

> **1번 검사를 고친 이유를 남긴다.** 첫 판에서 이 명령이 `^## S[0-9]+` 로 정의 목록을 뽑아
> `S9` 를 "미정의" 로 보고했다 — 실제로는 `## S8 · S9` 한 줄에 정의돼 있었다.
> **검사가 틀렸지 문서가 틀리지 않았다.** 이 검수가 설계문서에 대해 반복해서 지적한
> *"게이트가 잘못된 값에도 green/red 를 낸다"* 와 같은 클래스이므로, 숨기지 않고 기록한다.

> **한계 고지.** §1 의 행은 감사 리포트의 **발견 단위**(F1·F-01 등)이지 파일 단위가 아니다.
> 예컨대 T2 의 "메타 5종 듀얼 모드" 는 5개 파일이지만 발견 1건이다. 74 는 non-OK **판정 수**
> 이고 §1 의 행 수는 그것을 결정 단위로 묶은 것이라 **행 수와 74 가 1:1 로 같지 않다.**
> 이 문서가 증명하는 것은 *"모든 발견이 어떤 Stage 로 갔는가"* 이지 *"행 수가 74 인가"* 가 아니다.
> 후자를 원하면 감사 리포트의 커버리지 표를 직접 파싱해야 하고, 그것은 이 검수의 범위 밖이다.
